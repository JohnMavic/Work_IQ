📋 What This Is About

Agent Zero Phase 1 (Scan & Discovery) is the critical first filter in a 4-phase AI task management pipeline. It scans the user’s Microsoft 365 inbox and Teams messages to identify which messages require action — and which are just noise (newsletters, FYI, casual chats).

We optimized the AI prompt that drives this classification. Over 4 rounds, we tested 12 different prompt variants using a Squad-based parallel optimization approach: 3 AI “Prompt Engineers” created competing variants in each round, a Tester ran them against the live M365 inbox, and an Evaluator scored them against 5 success criteria.

The winner — Variant v1a from Round 1 — improved the score from 70/100 to 79/100 (+12.9%). After 3 consecutive rounds without further improvement, Phase 1 is considered fully optimized.

🎯 Success Criteria
Criterion Weight What It Measures How We Measure It Target
Classification 30% Correct identification of actionable vs non-actionable messages F1 score (Precision × Recall) against a manually reviewed “Golden Set” F1 ≥ 0.95 = 100pts
Subject Fidelity 25% Subject lines must be exact character-by-character copies String comparison: scan output title vs original email/Teams subject 100% match = 100pts
Deduplication 15% Correct recognition of messages that match existing tasks Compare “update” classifications against actual task IDs in database ≥95% correct = 100pts
Output Format 15% Valid JSON with all required fields (action, title, source, from, date, link) JSON schema validation + field value checks 100% valid = 100pts
Performance 15% Scan speed and reliability Time measurement: start to response <30s = 100pts, 30-60s = 90pts, 60-120s = 70pts, 120-300s = 50pts

Total Score = Σ(criterion_score × weight). A variant must score ≥2 points higher than the current best to be adopted. After 3 consecutive rounds without improvement, the phase is declared optimized.

🐙 Squad Methodology — How We Optimized

This optimization used Squad, a multi-agent orchestration framework. Instead of trying one prompt change at a time (sequential), we deployed a team of specialized AI agents that worked in parallel — testing 3 competing strategies per round simultaneously.

⚡ 3× Throughput
3 variants per round instead of 1. Tested 12 strategies in 4 rounds — sequentially this would have taken 12 rounds.
🧠 Persistent Memory
Squad's decisions.md accumulated learnings across rounds. Round 2 knew that "DON'T examples kill recall." Round 3 knew that "tone shifts break fidelity."
🔀 Strategy Diversity
Each engineer has a different optimization philosophy — structural, content, or compaction. This avoids tunnel vision and explores the solution space more broadly.

Team composition: Orchestrator (Lead) · PromptEngineer-A (structural) · PromptEngineer-B (content) · PromptEngineer-C (compaction) · Tester · Evaluator — all defined in .squad/ with individual charters, routing rules, and shared decisions.

✅ What Worked vs ❌ What Failed — Concrete Examples

✅ What Worked (v1a — 79/100)

The winning prompt added a Decision Framework that asks: “Does this message require the user to perform a specific, concrete action?” This single question dramatically improved classification.

Message Source Classification Why Correct
“Quarter End P09 March GS Open POs” Email ✅ New task Business request requiring review
“Könntest du den Aufbau der Extron Software dokumentieren?” Teams ✅ New task Clear deliverable directed at user
“Kurze Frage: haben wir einen Passwortmanager?” Teams ✅ New task Direct question needing an answer
“my combine button doesn’t work!” Teams ✅ New task Support request needing help
Casual chat: “Which one you think is closer?” Teams ✅ Skipped Vague snippet — no specific action
Scheduling: “Bin gerade noch in nem Call...” Teams ✅ Skipped Ephemeral scheduling — not a task

❌ What Failed

❌ v1b (Round 1, 71.5pts) — “When in doubt, leave it out”

Adding explicit DON’T examples with strong “leave it out” messaging caused the model to find only 1 task out of 33 messages. The examples were interpreted too literally — the model started skipping everything remotely ambiguous.

❌ v3b (Round 3, 57.8pts) — Tone shift broke subject fidelity

Simply changing “conservative” to “thorough” in the prompt’s tone — with identical rules — caused the model to start REWRITING subject lines. “Which one you think is closer to what it does?” became “Agent Zero naming — Which one you think is closer...” The model added context prefixes and combined multiple topics into single tasks, violating the #1 rule.

❌ v2a/v2b (Round 2, 0pts each) — Total model shutdown

Two variants found ZERO tasks out of 33 messages. v2a tried to reframe costs (“missing a task is permanent”), v2b tightened the dedup threshold to “100% certain”. Both caused the Copilot model to enter a state of total paralysis — it considered every message ambiguous and skipped everything.

💡 Core Insight: The Copilot model has a strong inherent bias toward caution. Any additional guidance — regardless of intent — tends to amplify this bias. Variant v1a hit a “sweet spot” where the prompt provides enough structure to improve classification without triggering over-cautious behavior. This sweet spot is fragile: even small changes destabilize it.

💡 Key Insights

🏆 Why v1a Wins

  • Structural clarity works. The Decision Framework gave Copilot unambiguous classification rules — raising Classification from 50 to 70 and Deduplication from 50 to 70.
  • Teams-specific rules closed the gap. Explicit Teams channel vs. chat rules eliminated the biggest source of missed items.
  • It preserved what already worked. Subject Fidelity (100) and Output Format (100) stayed perfect — no regressions.

❌ Why Every Challenger Failed

  • Content approaches (v1b, v1c): DO/DON'T examples and compaction hurt task discovery — Copilot's conservative bias means fewer examples = fewer found tasks.
  • Recall relaxation (v2a, v2b): Relaxing thresholds caused Copilot to return zero tasks — the model interpreted permissive language as "don't filter" rather than "find more".
  • Tone shifts (v3b): Switching from conservative to thorough framing dropped Subject Fidelity from 100 to 30 — the model lost precision when pushed to be inclusive.
  • Structural reordering (v4a, v4b, v4c): Moving sections around or adding surgical patches either had no effect or caused timeouts — the model was already at its structural optimum.
Core Insight: The Copilot model has a strong inherent bias toward caution in classification tasks. The only successful strategy was adding structural decision frameworks that gave explicit, unambiguous rules. Every attempt to relax, reword, or reframe the instructions either failed catastrophically (0 tasks found) or caused regressions. The v1a approach succeeded because it worked with the model's cautious nature rather than against it — providing clearer guardrails instead of looser ones.
